# master-ai — дизайн v1

> Дата: 2026-06-29. Локальный однопользовательский веб-инструмент подготовки НРИ-сессий — копия prep-ядра [Campaign Arks](https://www.campaignarks.com). Личный инструмент с подключением собственной LLM; open-source/мультиязычность — в последующих версиях.

## Цель и приоритеты

1. **Личный инструмент** для подготовки своих игр.
2. **Точная копия** prep-ядра Campaign Arks (типизированные документы, inline-AI, связанная кампания).
3. Open-source/мультиязычность — **потом**, не в v1.

## Состав v1

Включено:

- **A. Типизированные документы + редактор** — создание/редактирование NPC, локаций, секретов, сцен и т.д.
- **B. Inline-AI в документе** — предложения AI появляются прямо в тексте: принять / редактировать / отклонить.
- **C. AI-брейнсторм + апрувы** — разговор рождает структурированные черновики; очередь на добавление в базу.
- **D. Connected Campaign + поиск** — единая библиотека, линковка документов, полнотекстовый поиск.

Вне v1 (следующие версии):

- E. Авто-архивация использованного контента (секрет за столом → «раскрыт»).
- F. Play Materials / режим игры за столом.
- G. Импорт существующих материалов.
- Мультиязычность (i18n) и обвязка для OSS-контрибьюторов.

## Архитектурные решения

| Решение | Выбор | Причина |
|---|---|---|
| Модель запуска | Локально, один пользователь, данные на диске, без аккаунтов | Личный инструмент; локальный CLI нельзя дать чужим пользователям на общем сервере |
| Стек | Vite+React (фронт) + Node/Fastify (бэк) | Явные границы фронт/бэк; TS-окружение пользователя |
| Хранилище | Локальный SQLite (через Drizzle ORM) | Структурированные данные: связи, статусы, поиск; Drizzle легче и даёт прямой контроль над FTS5 |
| LLM | Абстракция провайдера: CLI сейчас, OpenAI-совместимый API заложен | Главная мотивация — использовать свою LLM через локальный CLI без оплаты токенов |
| Редактор | TipTap/ProseMirror + inline-подсказки как декорации | Единственный подход, дающий «точную копию» ощущения Campaign Arks |

## Модель данных (SQLite)

- **Campaign** — `id, name, system, description, createdAt`.
- **Document** — `id, campaignId, type, title, status, contentJson` (ProseMirror-документ), `fields` (JSON, типозависимые поля), `createdAt, updatedAt`.
- **DocumentType** — реестр типов как **данные, а не код** (чтобы повторить все типы документов Arks и добавлять свои): `key, label, icon, fieldsSchema, statuses`.
  - Стартовый набор: NPC, Локация, Фракция, Секрет, Сцена, Сессия, Предмет, Лор/Референс, Заметка (свободный документ).
  - Примеры типозависимых полей: NPC — статус; Секрет — флаг «раскрыт»; Сцена/арка — фазы.
- **Link** — связь между документами: `id, campaignId, fromDocId, toDocId, kind`.
- **Proposal** — черновик из брейнсторма, ждёт апрува: `id, campaignId, type, title, draftContent, fields, conversationId, status (pending|approved|rejected)`.
- **Conversation** / **Message** — история брейнсторм-чата.
- **Поиск** — SQLite **FTS5** по `title` + извлечённому тексту контента.

## Слой LLM (абстракция провайдера)

Единый интерфейс:

```
interface LLMProvider {
  complete(input: { system?: string; messages: Message[]; stream?: boolean }): AsyncIterable<string>
}
```

Реализации:

- **CliProvider (v1)** — запускает локальный CLI как подпроцесс (например, `claude -p` с потоковым выводом). Конфиг: команда, аргументы, модель. Типизированные ошибки: CLI не найден, ненулевой код выхода, таймаут.
- **ApiProvider (заложен, включается позже)** — OpenAI-совместимый `POST /chat/completions` (API-ключ + base URL).
- **FakeProvider** — детерминированный, для тестов.

Выбор активного провайдера — через локальный конфиг/настройки.

## Структура кода (монорепо, pnpm workspaces)

- **`packages/shared`** — TS-контракты и типы (Document, Proposal, API-схемы), общие для фронта и бэка.
- **`packages/server`** (Fastify):
  - `routes/` — campaigns, documents, links, search, brainstorm, llm.
  - `db/` — Drizzle + SQLite, миграции.
  - `llm/` — интерфейс провайдера + cli + api + fake.
  - `services/` — бизнес-логика.
- **`packages/web`** (Vite+React):
  - `pages/` — главная, кампания, редактор.
  - `editor/` — TipTap + расширение inline-подсказок.
  - `api/` — клиент к бэку.
  - состояние приложения.

## Inline-AI в редакторе (TipTap)

- Триггеры: выделить текст → действие («развернуть», «переписать»); slash-команда; «продолжить».
- Запрос → бэк → провайдер → ответ **стримится** обратно.
- Предложение рендерится как **ProseMirror-декорация** (отдельный suggestion-mark, визуально отличается) поверх документа, с кнопками **принять / редактировать / отклонить**.
- Документ не мутируется, пока предложение не принято. Принять — коммит текста; отклонить — снять декорацию.

## AI-брейнсторм + апрувы (Workshop)

- Чат-панель на кампанию.
- Обсуждение идеи → модель возвращает **структурированные черновики** (NPC/сцена/секрет — через инструкцию на JSON-формат).
- Черновики падают в **очередь апрувов**.
- Принять → создаётся Document нужного типа; Отклонить → черновик удаляется.

## UI

- **Главная** — список кампаний + кнопка «создать».
- **Кампания** с разделами:
  - **Workshop** — брейнсторм-чат + очередь апрувов + последние правки.
  - **Knowledge Base** — дашборд документов, сгруппированных по типам.
  - **Редактор документа** — открытие отдельного документа.
  - Глобальный поиск; кнопка **«Новый документ»**.

## Ошибки и тестирование

- Ошибки провайдера/стрима → типизированные ошибки → тост в UI; частичный стрим сохраняется.
- Тесты:
  - `shared` — контракты (unit).
  - `server` — сервисы и провайдер на `FakeProvider` (unit); роуты на in-memory SQLite (integration).
  - `web` — accept/reject inline-подсказки в редакторе (Vitest + Testing Library).
- TDD по ходу реализации.
