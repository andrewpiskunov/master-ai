# Редизайн режима проведения сессии: игровой чат с ИИ-мастером

**Дата:** 2026-07-03
**Статус:** утверждён

## Цель

Перевернуть модель экрана `PlaySession`: вместо «текст сессии слева, ассистент в боковой вкладке» — в центре экрана диалог с ИИ-мастером. Мастер вводит действия персонажей (персонаж выбирается кнопкой-чипом, не пишется руками), ИИ отвечает структурированно («Прочитай игрокам» / «Скрытое для мастера»), каждое действие автоматически попадает в лог событий с коротким заголовком и отметкой важности, клик по записи лога прокручивает чат к соответствующему сообщению.

## Утверждённые решения

| Вопрос | Решение |
|---|---|
| Старые панели (сценарий, просмотрщик, бой) | Сохраняются, уходят в правую колонку; чат — главный |
| Формат ответа ИИ | ИИ решает сам: действия — два блока, мета-вопросы — обычный текст |
| Создание записей лога | Каждое действие персонажа = запись; мета-вопросы в лог не попадают |
| Кнопки выбора актора | Чипы персонажей игроков + «+ NPC» (поиск) + «Мастер» |
| Отображение ответа | Лента чата, каждый ответ ИИ — крупная карточка с блоками |
| Возможности ассистента | Сохраняются: `new-doc`/`edit-doc`-блоки, кликабельные упоминания |

## Подход

Вариант B: новый компонент `GameChat` на клиенте + переиспользование серверной инфраструктуры (фоновые задачи `AssistantJobService`, таблицы `conversations`/`messages`, парсинг блоков ассистента выносится в общий модуль). Отдельная подсистема не создаётся.

## Компоновка экрана

Полноэкранный режим (`.play-mode`, как сейчас), три зоны:

```
┌─ Шапка: название · ● PLAY MODE · [Показ игрокам] · [След. сессия] · [Выйти] ─┐
├───────────────────────────────────────────────┬──────────────────────────────┤
│  ЦЕНТР — игровой чат                          │  ПРАВАЯ КОЛОНКА (~360px)     │
│  Лента сообщений:                             │ ┌ ЛОГ СОБЫТИЙ (верх, ~45%) ┐ │
│   · действие мастера (чип персонажа + текст)  │ │  ★ важные выделены       │ │
│   · карточка ответа ИИ:                       │ │  клик → скролл к сообщ.  │ │
│     ┌ 📖 Прочитай игрокам ────┐               │ └──────────────────────────┘ │
│     │ крупный читаемый текст  │               │ ┌ Вкладки:                 ┐ │
│     └─────────────────────────┘               │ │ Сценарий·Документы·Бой   │ │
│     ┌ 🔒 Скрытое для мастера ─┐               │ │ (всегда смонтированы,    │ │
│     │ приглушённый блок       │               │ │  display:none)           │ │
│     └─────────────────────────┘               │ └──────────────────────────┘ │
│  ─────────────────────────────────────────    │                              │
│  [Алдар][Мира][Торин][+ NPC▾][Мастер]         │                              │
│  [ Напишите действие персонажа...      ][➤]   │                              │
└───────────────────────────────────────────────┴──────────────────────────────┘
```

- **Центр** — игровой чат, заменяет вкладку «Ассистент». Карточка ответа ИИ: блок «Прочитай игрокам» — акцентный, крупный шрифт; «Скрытое для мастера» — приглушённый, с иконкой замка. Ответ без секций (мета-ответ) — обычная карточка.
- **Правая колонка**: сверху лог событий (всегда виден), ниже вкладки:
  - **Сценарий** — текст сессии, разбитый на секции по H2, с глазиками «только мастер» (`fields.sectionVisibility`) и кликабельными упоминаниями — как в текущем `.play-content`;
  - **Документы** — просмотрщик со стеком назад/вперёд и пинами (`fields.pins`) — как в текущем `.play-viewer`;
  - **Бой** — `CombatTracker` без изменений, включая «Из чата» (парсит участников из игрового чата).
  - Все вкладки всегда смонтированы, переключение через `display:none` (существующий паттерн — не терять состояние).
- Тумблер «Показ игрокам» дополнительно скрывает блоки 🔒 в чате и панель лога (плюс текущее поведение для секций сценария).
- Мобильная вёрстка: правая колонка складывается под чат или открывается по кнопке в шапке.

## Выбор актора

Над полем ввода — ряд чипов:

- активные персонажи игроков кампании (`type === "pc"`, `status === "active"`);
- **«+ NPC»** — выпадающий список с поиском по NPC кампании; выбранный NPC добавляется временным чипом на время сессии;
- **«Мастер»** — выбран по умолчанию; сообщение уходит как обычный вопрос мастера без привязки к персонажу.

Выбранный чип подсвечен и действует до явной смены. Сообщение-действие отправляется в LLM с префиксом «Действие (Алдар): …», в ленте отображается с именем и типом актора.

## Формат ответа ИИ и служебные блоки

Системный промпт ИИ-мастера: контекст кампании + текст сессии + хвост последних 20 реплик (текущая практика). Инструкции:

- На **действие персонажа** отвечать секциями `## Прочитай игрокам` (обязательно) и `## Скрытое для мастера` (если есть что скрывать), в конце — служебный блок лога:

  ~~~
  ```log
  {"title": "Алдар взломал замок в склеп", "important": false}
  ```
  ~~~

- На **вопрос мастера** (актор «Мастер») — обычный текст, без секций и без `log`-блока.
- Блоки ` ```new-doc``` ` / ` ```edit-doc``` ` / ` ```doc``` ` работают как в текущем ассистенте.

Клиент парсит ответ: секции → карточка с блоками; `log`-блок вырезается из отображения и становится записью лога, привязанной к сообщению. Упоминания документов кликабельны — открываются во вкладке «Документы».

## Лог событий

- **Хранение:** новая JSON-колонка `meta` в таблице `messages` (drizzle-миграция). У сообщения мастера: `{actorId, actorName, actorKind: "pc"|"npc"|"master"}`. У ответа ИИ на действие: `{log: {title, important}}`.
- **Панель лога — производная от сообщений беседы** (один источник правды): записи строятся из сообщений с `meta.log`.
- Клик по записи — плавный скролл к карточке в чате + кратковременная подсветка.
- Важные записи — звезда и акцентный цвет; мастер может переключить важность вручную (PATCH меты сообщения).
- Старый ручной textarea-лог (`fields.sessionLog`) из UI убирается. «Следующая сессия» (`sessionSummary`) получает на вход сериализованный лог событий + хвост игрового чата вместо `fields.sessionLog`.

## Сервер

- Игровой чат использует существующую беседу сессии (`conversations` по `document_id`) и фоновые задачи `AssistantJobService` (генерация переживает навигацию и закрытие вкладки; клиент поллит статус).
- `POST /api/documents/:id/assistant` расширяется полями `mode: "game"` и данными актора (`actorId`, `actorName`, `actorKind`); при `mode: "game"` сервер собирает игровой системный промпт.
- Новая миграция: колонка `messages.meta` (TEXT, JSON, default `'{}'`).
- Новый эндпоинт: `PATCH /api/messages/:id/meta` (переключение важности записи лога).
- Парсинг блоков ассистента (`doc`/`new-doc`/`edit-doc`) выносится из `DocumentAssistant.tsx` в общий модуль `assistant-blocks.ts`, используется обоими чатами.

## Что не меняется

- Боевой трекер (`CombatTracker.tsx`) — целиком, включая ИИ-заполнение «Из чата».
- Секционное скрытие сценария, пины и стек просмотрщика — переезжают в правую колонку как есть.
- Механика «Следующая сессия» (создание следующей сессии с ИИ-сводкой) — меняется только источник данных для сводки.
- Мастерская, помощник документа на странице документа, схема провайдеров LLM.

## Тестирование

- **Юнит (vitest):** парсер секций «Прочитай игрокам»/«Скрытое для мастера» и `log`-блока (включая ответы без секций, битый JSON в `log`-блоке); сборка игрового системного промпта на сервере; построение записей лога из сообщений с `meta`.
- **Ручная проверка (Playwright-прогон):** выбор чипа и отправка действия; рендер карточки с двумя блоками; появление записи в логе и клик-навигация к сообщению; переключение важности; тумблер «Показ игрокам» скрывает 🔒-блоки и лог; вкладки правой колонки не теряют состояние.

## Риски

- ИИ может не соблюдать формат секций/`log`-блока — парсер обязан деградировать мягко: ответ без секций показывается обычной карточкой, действие без `log`-блока получает запись лога с заголовком из первых слов действия (`important: false`).
- Старые сессии с непустым `fields.sessionLog`: содержимое не мигрируется и не отображается в новом UI; при генерации сводки, если игровой лог пуст, а `fields.sessionLog` непуст — использовать его (обратная совместимость).
