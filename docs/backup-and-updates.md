# Резервные копии и обновления

## Какой формат выбрать

| Формат | Что сохраняет | Для чего подходит |
| --- | --- | --- |
| JSON кампании | Одну кампанию: документы, беседы, сообщения, предложения, связи и статистику ИИ. Поле API-ключа исключается. | Перенести кампанию в другую установку или сделать отдельную копию. |
| Полная SQLite-копия | Все кампании, содержимое и настройки, включая API-ключи. | Восстановить установку целиком или сохранить состояние перед обновлением. |
| Markdown или печать | Читаемый документ с материалами кампании. | Читать, печатать и передавать материалы; обратного импорта этих форматов нет. |

## Перенести одну кампанию

В «Управлении кампанией» откройте раздел «Экспорт и импорт» и нажмите «Экспорт в JSON». Для загрузки файла в другую установку используйте «Импорт из JSON» в том же разделе.

Импорт создаёт новую кампанию и новые идентификаторы записей. Существующая кампания остаётся на месте; повторный импорт создаёт ещё одну копию. После импорта введите API-ключ заново, если используете API-провайдер.

JSON содержит тексты документов и переписки. Удаление поля API-ключа не очищает секреты, которые могли попасть в эти тексты. Перед публикацией проверьте содержимое файла.

## Сделать полную копию

В «Управлении кампанией» → «Экспорт и импорт» нажмите «Скачать резервную копию». Сервер отдаст снимок всей базы одним файлом `.sqlite`; приложение можно оставить запущенным.

Храните файл за пределами рабочего каталога проекта. В нём есть все кампании и сохранённые API-ключи, поэтому не прикладывайте его к публичным issues.

При старте сервер также создаёт файл `packages/server/data/backups/master-ai-ГГГГ-ММ-ДД.sqlite`. Дата берётся по UTC. Если копия за этот день уже есть, новая не создаётся. После создания копии сервер оставляет последние семь файлов этого формата.

Это проверка при запуске, а не фоновое расписание: если сервер работает несколько дней без перезапуска, новых ежедневных копий не появится. Автоматическая копия создаётся после открытия базы и применения миграций. Перед обновлением кода сохраните отдельную полную копию вручную.

## Восстановить базу

1. Остановите `pnpm dev` и убедитесь, что процесс API завершён.
2. Сохраните текущие `master-ai.sqlite`, `master-ai.sqlite-wal` и `master-ai.sqlite-shm` из `packages/server/data` в отдельном каталоге, если эти файлы есть. Это сохранит состояние перед восстановлением.
3. Поместите выбранный файл полной резервной копии в `packages/server/data` под именем `master-ai.sqlite`. Старые файлы `master-ai.sqlite-wal` и `master-ai.sqlite-shm` не должны оставаться рядом с ним.
4. Запустите `pnpm dev` и проверьте список кампаний, документы и настройки нейросети.

Не заменяйте базу, пока сервер работает. Простое копирование одного рабочего `.sqlite` при активной записи может пропустить изменения из WAL; используйте скачанный снимок или штатную автоматическую копию.

При восстановлении под другим commit учитывайте миграции: сервер применяет их автоматически при запуске. Для возврата к старому коду используйте копию базы, сделанную до соответствующего обновления. Автоматического отката миграций нет.

## Обновить приложение

1. Пока текущая версия работает, скачайте полную резервную копию.
2. Остановите приложение. Сохраните свои изменения кода и обновите checkout до выбранного commit или ветки.
3. Переключитесь на версию Node.js из `.nvmrc`. При использовании nvm выполните `nvm install` и `nvm use`.
4. Выполните из корня:

```sh
corepack enable
corepack prepare pnpm@9.15.9 --activate
pnpm install --frozen-lockfile
pnpm check
pnpm dev
```

После старта проверьте кампанию и подключение ИИ. Не удаляйте `packages/server/data` и `.env` при обновлении зависимостей или кода.
