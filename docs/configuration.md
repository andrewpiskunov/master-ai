# Настройка

Есть два уровня настроек: команда CLI для всего сервера и выбор нейросети для отдельной кампании. Настройки кампании открываются через «Управление кампанией» → «Нейросеть».

## CLI по умолчанию

Сервер запускает команду `claude` с аргументом `-p`. CLI-клиент нужно установить и авторизовать отдельно. Он должен быть доступен в `PATH` того терминала, из которого запускается `pnpm dev`.

Чтобы изменить команду, создайте `.env` в корне проекта на основе [.env.example](../.env.example):

```dotenv
MASTER_AI_LLM=cli
MASTER_AI_LLM_CMD=claude
MASTER_AI_LLM_ARGS=-p
```

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `MASTER_AI_LLM` | `cli` | Тип серверного провайдера. Поддерживается только `cli`. |
| `MASTER_AI_LLM_CMD` | `claude` | Исполняемая команда CLI. |
| `MASTER_AI_LLM_ARGS` | `-p` | Аргументы команды, разделённые пробелами. |

Штатная команда разработки сервера читает корневой `.env`. После изменения файла перезапустите `pnpm dev`. Можно передать эти же переменные через окружение процесса.

В настройках кампании кнопка CLI и пояснение показывают команду, настроенную на сервере: например, «Codex (CLI)» для `codex` или «Claude Code (CLI)» для `claude`. Выбор CLI в кампании использует эту общую настройку.

Сервер передаёт запрос в стандартный ввод CLI и читает текст ответа из стандартного вывода. Процесс запускается из временного каталога. При замене команды используйте клиент с таким же способом работы. Строка аргументов делится по пробелам: сложное shell-экранирование и аргументы с пробелами не поддерживаются.

### Codex CLI

Для Codex, установленного и авторизованного на этом компьютере, можно использовать такую конфигурацию:

```dotenv
MASTER_AI_LLM=cli
MASTER_AI_LLM_CMD=codex
MASTER_AI_LLM_ARGS='exec --model gpt-6.1-sol --config model_reasoning_effort="medium" --skip-git-repo-check --sandbox read-only --ephemeral --color never -'
```

Модель и уровень рассуждений здесь заданы для приложения. После изменения `.env` перезапустите сервер.

## OpenAI-совместимый API для кампании

1. Откройте кампанию и перейдите в «Управление кампанией».
2. В разделе «Нейросеть» выберите «OpenAI API».
3. Заполните API-ключ, название модели и при необходимости Base URL. Дождитесь сохранения полей.

Пустые поля модели и Base URL используют значения из кода: `gpt-4o-mini` и `https://api.openai.com/v1`. Для совместимого сервиса укажите его модель и базовый адрес с API-префиксом, например `https://host/v1`. Сервер добавляет к нему `/chat/completions` и ожидает потоковый ответ Chat Completions.

С непустым API-ключом выбранные параметры применяются к ИИ-функциям этой кампании. Пустой API-ключ включает CLI-провайдер, даже если переключатель стоит на «OpenAI API». Совместимый сервис должен принимать используемый приложением формат запросов; поддержка любого сервиса с похожим названием API не гарантируется.

Ключ вводится в интерфейсе и хранится в локальной базе. Переменные вроде `OPENAI_API_KEY` приложение не читает; в корневом `.env` настройка API-ключа не предусмотрена.

## Изображения в чатах и сущностях

Вставьте картинку через **Cmd+V / Ctrl+V** в поле сообщения мастерской, помощника документа или игрового чата. Можно также выбрать файл кнопкой «Изображение». Перед отправкой появится превью с возможностью убрать вложение; текст сообщения необязателен. Поддерживаются PNG, JPEG и WebP: до четырёх изображений в сообщении, каждое до 10 МиБ. Для API нужна модель с поддержкой изображений; CLI-вложения поддерживаются через Codex и Claude Code.

У документа откройте вкладку **«Изображения»**, вставьте или выберите файлы и нажмите «Прикрепить к сущности». Кнопка **«Создать иллюстрацию»** использует описание сущности и ваш запрос, запускает серверный Codex и прикрепляет результат к галерее. Для этого настройте `MASTER_AI_LLM_CMD=codex` и авторизуйте CLI; генерация использует встроенный imagegen и лимиты Codex. Эта операция работает через Codex и при выбранном API для текстовых запросов кампании.

Нажмите на изображение в галерее или чате, чтобы открыть его поверх приложения. В просмотре доступны переключение стрелками, масштаб 1:1 и скачивание; Esc закрывает просмотр и возвращает к карточке.

Карточки, списки, чаты и галереи загружают уменьшенные WebP-копии с учётом плотности экрана. Оригинал загружается при открытии полного просмотра, скачивании или показе на экране игроков. Аватарки заполняют рамку с обрезкой краёв; полная композиция остаётся доступна в просмотре.

Корзина в галерее карточки, выборе обложки и полном просмотре удаляет изображение после подтверждения. Оно исчезает из всех карточек и переписок кампании; выбор аватара или обложки сбрасывается. Если в галерее остались изображения, аватаркой становится первое из них. Удалённая картинка убирается и с открытого экрана игроков. Крестик **«Открепить»** убирает только связь с текущей карточкой и сохраняет файл в кампании.

У любой карточки есть аватарка в шапке и списке материалов. По умолчанию используется первое изображение галереи. Во вкладке **«Изображения»** можно выбрать другое кнопкой **«Сделать аватаром»** или вернуть автоматический выбор. Аватарка входит в экспорт кампании; её смена не меняет текст карточки.

У кампании можно выбрать обложку на главной странице: нажмите кнопку смены обложки на её карточке, загрузите файл или выберите изображение из этой кампании. Поиск на главной учитывает название, описание и систему; рядом доступны фильтр по системе и сортировка по активности, дате создания или названию. Обложки сохраняются при экспорте и импорте.

Сгенерированные иллюстрации получают имена по карточке, например **«Олдос Суини — портрет.png»**. Подпись изображения и ссылка **«Карточка: …»** показываются отдельно. Имена сущностей и исходные файлы Codex при этом не меняются.

Во время сессии откройте вкладку **«Изображения»**, выберите сущность и её иллюстрацию. Нажатие на превью открывает просмотр для мастера. Кнопка **«Экран игроков»** открывает отдельное окно того же браузера: его можно перенести на второй монитор и развернуть на весь экран.

Кнопка **«Показать игрокам»** отправляет в это окно выбранное изображение. Подписи выключены по умолчанию; мастер включает их отдельно. Кнопка скрытия убирает картинку. В окно игроков передаются только сведения о выбранном изображении — тексты, характеристики и заметки сущностей туда не попадают.

Выбор сущности открывается отдельным окном с поиском по названию и типу, фильтрами и миниатюрами. По умолчанию показываются сущности с изображениями; режим **«Все сущности»** включает остальные карточки. Вкладка **«Изображения»** расположена перед **«Боем»**.

Мастерская, помощники карточек и игровой чат поддерживают одинаковые действия с изображениями. Можно попросить создать иллюстрацию, прикрепить загруженный референс или сделать картинку главной. Например: **«Создай изображение дома без мистических деталей и сделай его главным; прежнее оставь в галерее»**. Создание через Codex выполняется сервером; результат появляется рядом с ответом после проверки файла. Ошибка одного действия не скрывает успешные прикрепления.

Для правки готовой картинки прикрепите исходник к сообщению и опишите изменения, например **«Убери надпись, сохрани остальную композицию»**. Исходное изображение передаётся отдельному процессу Codex вместе с запросом; можно использовать до четырёх изображений. Приложение сохраняет новую версию отдельно. Ошибки авторизации, лимита, недоступного инструмента или отсутствующего исходника показываются понятным сообщением.

Во все эти диалоги можно вставлять изображения через **⌘V / Ctrl+V** или выбирать файл. У изображения в переписке кнопка **«К сущности»** открывает прикрепление; в помощнике карточки текущая сущность уже выбрана. Флажок **«Сделать главным изображением»** назначает аватарку. Галерея и аватарка обновляются после действия; черновик текста сохраняется.

В мастерской попросите создать изображения и прикрепить их к нужным карточкам. Codex передаёт приложению реальные файлы и идентификаторы целевых документов; сервер импортирует их в галереи. Под ответом появляются проверенные превью, ссылки на карточки и ошибки для файлов, которые не удалось прикрепить. Текст карточки при этом не заменяется. Под загруженной в диалог картинкой кнопка **«К сущности»** позволяет выбрать карточку вручную.

Для импорта файлов мастерская читает только каталог `~/.codex/generated_images`. Если ваш Codex сохраняет изображения в другом месте, задайте абсолютный путь в `MASTER_AI_GENERATED_IMAGES_DIR` и перезапустите сервер. Принимаются PNG, JPEG и WebP до 10 МиБ, до 50 прикреплений за ответ. Ссылки на произвольные локальные файлы не импортируются. После импорта изображения хранятся в SQLite и больше не зависят от исходного каталога Codex.

Генерация продолжается при переходе в другой раздел; при возвращении вкладка подхватит её статус. Кнопка «Стоп» прерывает задачу. Изображения хранятся в SQLite и входят в резервную копию и JSON-экспорт кампании. JSON-импорт принимает файлы до 512 МиБ.

## Адреса и данные

| Параметр | Значение при штатном запуске |
| --- | --- |
| Интерфейс Vite | `http://localhost:5173` |
| API Fastify | `http://127.0.0.1:5174` |
| База SQLite | `packages/server/data/master-ai.sqlite` |
| Автоматические копии | `packages/server/data/backups/` |

Порт API и путь рабочей базы заданы в серверном коде, порт и прокси интерфейса — в конфигурации Vite. Переменные для их изменения не предусмотрены. При занятом порте Vite может выбрать следующий свободный порт и вывести его в терминал.

При использовании ИИ контекст отправляется выбранному клиенту или API. О хранении секретов и границах локального запуска читайте в [SECURITY.md](../SECURITY.md).
