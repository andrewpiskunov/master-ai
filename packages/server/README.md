# @master-ai/server

Сервер Master AI: HTTP API на Fastify, база SQLite и обращения к ИИ. При локальном запуске слушает `http://127.0.0.1:5174`. Требования к Node.js, установка зависимостей и запуск всего приложения описаны в [главном README](../../README.md).

## Команды

Выполняются из корня репозитория:

```sh
pnpm --filter @master-ai/server dev
pnpm --filter @master-ai/server test
pnpm --filter @master-ai/server typecheck
```

`dev` запускает `src/main.ts` через tsx с перезапуском при изменениях. Он читает `.env` в корне репозитория; без этого файла используются переменные окружения и значения по умолчанию. Настройку провайдера по умолчанию читает `llm/config.ts`, а настройки конкретной кампании обрабатывает `llm/resolve.ts`.

`test` запускает Vitest. Тесты API создают приложение через `buildApp`, используют временную базу или SQLite в памяти и подставляют тестовый провайдер ИИ. `typecheck` проверяет TypeScript без генерации файлов. Отдельной production-сборки серверного пакета нет; пакет `@master-ai/shared` предоставляет TypeScript-исходники напрямую.

## Структура

```text
src/
  main.ts                 запуск, открытие базы, резервная копия и индексация
  app.ts                  buildApp и создание общих сервисов
  routes/
    dependencies.ts       типы зависимостей маршрутов
    campaign.ts           кампании и фоновое приветствие
    document.ts           документы и реестр их типов
    link.ts               связи между документами и поиск
    workshop.ts           мастерская, проверка мира и следующая сессия
    conversation.ts       история бесед и метаданные сообщений
    assistant.ts          фоновые задачи помощника документа
    proposal.ts           просмотр, принятие и отклонение предложений
    llm.ts                поток генерации и статистика расхода
    transfer.ts           импорт/экспорт кампании и скачивание базы
  services/               работа с данными и логика приложения
  db/                     схема Drizzle, подключение и миграции при открытии
  llm/                    интерфейс провайдера, CLI и OpenAI-совместимый API
drizzle/                  SQL-миграции и журнал Drizzle
```

Тесты `*.test.ts` лежат рядом с проверяемым кодом. `buildApp({ db, llm?, sqlite? })` создаёт экземпляр Fastify без открытия порта. Необязательный `sqlite` нужен для скачивания резервной копии; без него этот маршрут возвращает `503`.

Маршруты проверяют HTTP-запросы и вызывают сервисы. `app.ts` создаёт сервисы и передаёт каждому модулю маршрутов нужную часть типизированных зависимостей. Сервисы используют Drizzle и интерфейс `LLMProvider`; адаптеры в `llm/` отвечают за вызов внешнего процесса или HTTP API. Общие типы, схемы Zod и реестр документов приходят из `@master-ai/shared`. Зависимости от `@master-ai/web` у сервера нет.

## База и миграции

Команда `pnpm --filter @master-ai/server dev` работает из каталога пакета, поэтому база сохраняется в `packages/server/data/master-ai.sqlite`, а ежедневные копии в `packages/server/data/backups/`. Пути в `main.ts` относительны текущему рабочему каталогу. При старте сервер создаёт копию за текущую дату, если её ещё нет, и оставляет последние семь ежедневных копий.

`db/client.ts` включает режим WAL и применяет миграции из `drizzle/` при каждом вызове `createDb`. Отдельная команда применения миграций для обычного запуска не нужна.

При изменении модели данных:

1. Измените `src/db/schema.ts`.
2. Создайте миграцию командой `pnpm --filter @master-ai/server exec drizzle-kit generate`.
3. Проверьте SQL и изменения в `drizzle/meta/`, затем запустите тесты и проверку типов.

Существующие миграции сохраняйте: по ним приложение обновляет уже созданные базы. Перед запуском новой версии сделайте копию пользовательских данных. Внутренние тесты базы используют тот же набор миграций, что и приложение.
