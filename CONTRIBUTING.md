# Участие в разработке

Помочь проекту можно исправлением ошибки, улучшением интерфейса, документации или примеров кампаний. Обсуждения и pull requests можно писать по-русски или по-английски.

## Перед началом

Проверьте [открытые issues](https://github.com/andrewpiskunov/master-ai/issues), чтобы не повторять уже описанную проблему. Для заметного изменения поведения сначала создайте issue с задачей и примером использования. Небольшое исправление можно сразу прислать в pull request.

Об уязвимостях сообщайте по [инструкции безопасности](SECURITY.md). Общение в проекте подчиняется [правилам поведения](CODE_OF_CONDUCT.md).

## Рабочее окружение

Нужны Git, Node.js 22 и pnpm 9.15.9. Точная версия Node.js записана в [.nvmrc](.nvmrc). Команды выполняются из корня репозитория:

```sh
corepack enable
corepack prepare pnpm@9.15.9 --activate
pnpm install --frozen-lockfile
pnpm dev
```

Подробности запуска и подключения ИИ: [первый запуск](docs/getting-started.md), [настройка](docs/configuration.md). Для тестов API-ключи и установленный ИИ-клиент не нужны.

## Как подготовить изменение

1. Создайте ветку от актуального состояния репозитория.
2. Меняйте код в пакете, которому он принадлежит. Схемы обмена данными находятся в `packages/shared`, HTTP и хранение данных — в `packages/server`, интерфейс — в `packages/web`.
3. Если меняется поведение, добавьте проверку, которая воспроизводит задачу или ошибку. Для правок текста достаточно проверить команды и ссылки.
4. Обновите документацию, если поменялись запуск, настройки или поведение приложения.
5. Запустите общую проверку:

```sh
pnpm check
```

Проверки по отдельности и устройство пакетов описаны в [руководстве разработчика](docs/development.md).

## Что включить в pull request

Опишите проблему и результат изменения. Укажите связанное issue и выполненные проверки. Для заметного изменения интерфейса приложите скриншоты с вымышленными данными.

Не добавляйте в репозиторий `.env`, API-ключи, рабочую базу, резервные копии и личные материалы кампаний. Для воспроизведения подходит [демонстрационная кампания](examples/README.md).

Сохраняйте имена workspace-пакетов и публичные экспорты `@master-ai/shared`, если задача не требует изменения контракта. Изменения базы оформляйте новой миграцией в `packages/server/drizzle`; уже применённые миграции не переписывайте.

Интерфейс приложения ведётся на русском языке. Новый текст должен называть конкретное действие или результат; ошибки должны помогать понять, что делать дальше.

Вклад в проект распространяется на условиях [MIT](LICENSE).
